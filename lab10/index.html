Lab 10: Voice Interaction with Data Visualizations

This visualization shows how commercial transactions among companies evolve over 60 days. Companies are represented as nodes, while commercial relationships are represented as links. The network changes over time as relationships appear, disappear, and change in transaction activity.

The datasets are fabricated for visualization practice and do not represent real companies or transactions.

Data Structure

Company data: Company ID, company name, sector, and region.

Transaction data: Date, day, source company, target company, transaction amount, transaction type, and transaction count.

Network structure: Companies are represented as nodes and commercial transactions are represented as undirected links between companies.

Animated Commercial Network

The network displays the commercial relationships active on the selected day. Company nodes remain persistent across time to help preserve the mental map, while links enter and exit as relationships change.

Design Description

1. Visual channels. Node color represents company sector. Node shape represents geographic region. Node size represents current transaction volume. Link width represents transaction amount, while link opacity represents transaction count.

2. Temporal encoding. Time is represented through animation, the interactive time slider, and the date selector. As the selected day changes, active commercial relationships are updated. New relationships fade into the network and inactive relationships fade out.

3. Mental map preservation. The same company nodes are maintained throughout the animation instead of recreating the entire network for every day. The force simulation is gently restarted when links change. This helps users follow companies while the network evolves.

Temporal Network Analysis

1. How does overall connectivity change across the 60 days?

Connectivity fluctuates over time, but the later period appears denser than the beginning. On Day 3, the network contains 3 active links connecting 6 companies; on Day 57, it contains 10 active links connecting 12 companies. These snapshots illustrate a broader set of active commercial relationships later in the period. They are examples of individual days, rather than proof that connectivity increases monotonically.

2. Which companies appear most commercially active?

Fusion Electronics, Ion Systems, Cedar Retail, and Harbor Shipping are visually prominent on several days. Larger nodes indicate greater transaction volume, while multiple visible links indicate more active relationships. Their central positions in the force-directed layout help with visual exploration, but position alone should not be interpreted as a formal centrality measure.

3. When does the network become more fragmented?

The network is relatively fragmented on some earlier days. For example, Day 10 shows 8 active links connecting 11 companies, while Day 11 shows 3 active links connecting 6 companies. This change is consistent with a short-term reduction in active connectivity. Later in the timeline, particularly around Day 40 onward, the network more often appears to reconnect after highly active days. This is a visual pattern in the displayed snapshots, not evidence of a causal mechanism.

4. Which relationships appear or disappear?

Links change as the active transactions change. The Harbor Shipping–Juniper Stores relationship is visible on Day 9 but is absent in later snapshots. By Day 59, relationships such as Ion Systems–Apex Textiles and Fusion Electronics–Ion Systems are visible. Link width and opacity help compare transaction amount and transaction count, respectively.

5. How does cross-regional activity appear to change?

Connections between nodes with different shapes indicate relationships between companies in different regions. On Day 9, Granite Wholesale (Europe) connects with Keystone Materials (Asia). On Day 59, visible cross-regional examples include Ion Systems (North America)–Apex Textiles (Asia) and Fusion Electronics (Asia)–Ion Systems (North America). These examples illustrate cross-regional links in selected snapshots; they do not by themselves establish a trend for the entire period.

Lab 10: Interaction Design

Previous visualization. This submission extends the existing Lab 7 temporal commercial-network visualization. It preserves the D3.js network, visual encodings, timeline, and date picker rather than rebuilding the visualization.

Interaction modality and task. Voice commands support temporal navigation and targeted exploration. Users can move between days, play or pause the animation, emphasize a region, or highlight a selected company and its active connections.

Command Visualization response
“Next day” / “Previous day” / “Go to day 12” Changes the selected time step and updates the active network.
“Play” / “Pause” / “Reset” Controls the existing temporal animation. Reset returns to Day 1 and clears voice emphasis.
“Show Europe” or another data region Emphasizes companies in the requested region and relationships incident to them.
“Highlight [company name]” Highlights the named company and its active transaction connections.

Feedback and fallback. The interface displays the recognized transcript, listening state, and the action taken. If recognition fails or is unavailable, the original Play, Pause, Reset, slider, date picker, hover tooltips, and mouse interaction remain available. The microphone is activated only after the user clicks Start Voice Control.

Lab 10: Design Reflection

I extended my Lab 7 temporal commercial-network visualization with voice interaction while preserving the original D3.js network, visual encodings, timeline, date picker, and mouse controls. Voice commands support temporal navigation, playback control, regional emphasis, and company-level exploration. These tasks suit voice because users can issue short commands to move between time steps or focus on a company without locating a small control or node in a dense network. For example, “Go to day 12” supports temporal comparison, while “Highlight [company name]” supports exploration of a company's active transaction connections.

The interface provides transcript and action feedback so users can check how their commands were interpreted. The original buttons, slider, date picker, and mouse interactions remain available if voice recognition fails or is unavailable. Potential limitations include browser compatibility, microphone permissions, background noise, and errors when recognizing company names. These limitations mean voice should supplement rather than replace conventional interaction. Overall, this extension explores how speech can make common navigation and selection tasks more direct while preserving access to the original visualization.
